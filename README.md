# Client Radar

**Рабочий сайт:** https://client-radar-zeta.vercel.app/

Живой MVP аналитического инструмента для клиентского менеджера корпоративного банка.

## Текущая логика

1. Пользователь вводит только 10-значный ИНН юридического лица.
2. Сервер идентифицирует компанию через DaData.
3. Из профиля компании формируются точные поисковые признаки: официальное название, руководитель, ОКВЭД и доступные корпоративные связи.
4. Новости ищутся по контуру из 20 доверенных источников через агрегирующие каналы.
5. Публикации фильтруются по релевантности к конкретному юрлицу.
6. События группируются, дубли удаляются.
7. Событие помечается как подтвержденное, если есть официальный/реестровый источник или минимум два независимых доверенных подтверждения.
8. Отраслевые события показываются только при достаточном подтверждении.
9. Интерфейс показывает подтвержденную хронологию как доказательную базу.
10. Отдельный LLM-слой получает карточку компании, релевантные публикации и отраслевые бенчмарки и строит 4–6 приоритетных стратегических тезисов по логике: факт → значение для бизнеса → действие → роль банка → источник дохода.
11. Каждый стратегический тезис содержит ссылки на публикации, а гипотезы явно отделены от фактов.

## Важно

Demo-новости удалены. Если не настроен DADATA_TOKEN, реальный поиск по ИНН не запускается.

Учредитель не приравнивается к конечному бенефициару. Бенефициар должен отображаться только при наличии отдельного подтвержденного источника.

## Переменные окружения

DADATA_TOKEN=
OPENAI_API_KEY=
OPENAI_MODEL=gpt-6.1-sol

## Vercel

Добавьте DADATA_TOKEN и OPENAI_API_KEY в Project Settings → Environment Variables и выполните Redeploy. OPENAI_MODEL опционален; по умолчанию используется gpt-6.1-sol. Ключ OpenAI используется только на серверной стороне и не попадает в браузер.

## Ограничения MVP

Cross-source verification и правила остаются первым слоем и отвечают за идентификацию компании, релевантность и хронологию. LLM используется только вторым слоем — для смыслового синтеза и стратегических гипотез. Если OPENAI_API_KEY не задан, сайт продолжает работать в режиме хронологии без глубокого анализа.
